# 智能驾驶就业补强教程：从 Waymax 小实验到初级岗位

## 这份教程解决什么问题

当前 Waymax 30 天课程完成后，你能解释并复现一个 CPU 状态仿真实验，
但还不能据此声称自己已经能负责量产自动驾驶系统。

本教程补充就业需要的工程能力，主线选择：

```text
Waymax 状态仿真
  -> C++ 车辆模型
  -> 控制器
  -> 路径/轨迹规划
  -> ROS 2 节点
  -> 评测、回放、故障定位
  -> 可展示作品集
```

不要求先“精通全部智能驾驶”。现实目标是：

```text
一条方向做深：规划/控制或仿真/评测
周边能力够用：Linux、Git、Python、ROS 2、测试
能展示作品：代码、实验、失败分析、设计取舍
```

这是一份 **12 周补强计划**，默认继续使用本机现有数据和 CPU。
不下载大数据，不启动 CARLA，不修改系统驱动，不要求 GPU。

## 学完当前 30 天后，能不能投简历

可以开始投递，但岗位要匹配：

| 目标岗位 | 当前课程后的状态 | 还要补什么 |
| --- | --- | --- |
| 仿真/评测实习生 | 接近入门要求 | C++、测试、指标工具、报告 |
| 数据/回放工具开发 | 有基础 | C++/Python 工程、文件格式、可复现 |
| 规划控制初级岗位 | 还不够 | 控制、规划、C++、ROS 2 |
| 感知算法岗位 | 不匹配 | 相机/LiDAR、检测、跟踪、深度学习 |
| 资深量产算法岗位 | 不够 | 生产系统经验、实车/传感器、长期项目经验 |

不要把“完成教程”写成“精通自动驾驶”。简历中应写成：

> CPU-only Waymax state simulation，包含 expert、固定动作对照、
> 行为克隆、指标统计、checkpoint reload 和证据校验。

## 先选方向

### A. 规划/控制主线（推荐）

适合目前的 Waymax 基础。重点是：

- 车辆运动学；
- PID、Pure Pursuit、Stanley、MPC；
- 路径和速度规划；
- 碰撞检查；
- C++/ROS 2 集成；
- 闭环评测。

### B. 仿真/评测与数据工程

适合喜欢工具、实验和可复现性的人。重点是：

- scenario 转换；
- TFRecord/JSON/CSV/Parquet；
- 回放和指标；
- 自动化测试；
- 资源测量；
- 失败样本定位。

### C. 感知方向

需要另开一条线：

- 图像和点云；
- 相机/LiDAR 标定；
- 目标检测；
- 多目标跟踪；
- 深度学习训练和部署。

本教程默认 A 为主、B 为副；C 只安排入门认知，不把三条线同时学深。

## 12 周路线

可执行课件已拆分到
[就业强化课程包](autodrive-job-track/README.md)，每周有独立目标、命令、
验收和作品集产物。本文保留总览；学习时从课程包索引进入。

### 第 1 周：C++ 和 Linux 工程基础

**目标**

- 能写 C++17 小程序；
- 能用 CMake 构建；
- 能写单元测试；
- 能用 gdb 定位一个越界或数值错误。

**学习内容**

```text
变量/引用/const
class/struct
vector/array/string
智能指针与 RAII
异常和错误返回
头文件与命名空间
CMake target
CTest 或现有测试框架
```

**练习**

创建 `projects/job-track/cpp-basics/`：

```text
include/vehicle_state.hpp
src/main.cpp
tests/state_test.cpp
CMakeLists.txt
```

实现 `VehicleState {x, y, yaw, speed}`，并测试：

- 默认构造值；
- 单位转换；
- 非有限数拒绝；
- 复制和移动不破坏值。

**验收**

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

不要只让程序“能编译”；必须有失败测试，证明测试确实会拦截错误。
可配合 CMake 官方 Tutorial，按“可执行文件、库、依赖、测试和安装”逐步扩展
这个小项目。

### 第 2 周：坐标变换和车辆运动学

**目标**

- 分清 global/map/vehicle 坐标；
- 理解 yaw、速度和曲率；
- 能用 C++ 重写一个最小 bicycle model。

**练习**

实现：

```cpp
State step(const State& state, const Action& action, double dt);
```

其中：

```text
Action = {acceleration_mps2, curvature_inv_m}
dt = 0.1 s
```

加入：

- 加速度和曲率边界裁剪；
- NaN/Inf 拒绝；
- 速度不能无意变成负数；
- 与 Day 05 中的 Python/Waymax 公式对照。

**验收**

给同一初始状态输入：

```text
[0, 0]       -> 近似直行
[-2, 0]      -> 减速直行
[0, 0.05]    -> 改变朝向
```

输出 80 步 CSV，并画出轨迹。必须能解释每列的单位。

### 第 3 周：控制器

**目标**

- 明白“目标轨迹”和“控制动作”之间的关系；
- 能实现至少一个闭环控制器；
- 能解释稳定性、误差和饱和。

**顺序**

1. PID 速度控制；
2. Pure Pursuit 横向控制；
3. Stanley 横向控制；
4. 与固定 brake 对照；
5. 对控制量做限幅。

**练习**

给定一条二维参考轨迹：

```text
目标点 -> 最近点 -> 横向误差 -> 曲率命令
目标速度 -> 速度误差 -> 加速度命令
```

输出：

```text
tracking_error.csv
controller_summary.json
trajectory.png
```

**验收**

- 直线轨迹不会持续蛇形；
- 曲线轨迹误差有明确统计；
- action 到达边界时有计数；
- 测试覆盖空轨迹、单点轨迹和不连续轨迹。

### 第 4 周：路径、轨迹和碰撞检查

**目标**

区分三个词：

| 词 | 含义 |
| --- | --- |
| Path | 几何路线，主要回答“往哪里走” |
| Speed profile | 速度随时间变化 |
| Trajectory | 带时间的路径和状态 |

**练习**

实现一个小型 planner：

```text
输入：当前状态、参考路径、障碍物矩形
输出：未来 3–5 秒的离散 trajectory
```

先不追求复杂搜索算法，优先完成：

- 最近路径点；
- 前视点；
- 速度上限；
- 轴对齐矩形碰撞检查；
- 无可行轨迹时返回明确错误。

**验收**

至少构造三个场景：

1. 没有障碍物；
2. 轨迹正前方有障碍物；
3. 障碍物在旁边但不应误报。

### 第 5 周：ROS 2 基础

**目标**

- 会写 publisher/subscriber；
- 会看 topic 和消息；
- 会理解时间戳和坐标系；
- 会录制和回放一小段数据。

**练习节点**

```text
state_publisher：发布 VehicleState
controller_node：订阅 VehicleState，发布 ControlCommand
metrics_node：订阅状态和控制，输出误差
```

建议消息字段：

```text
timestamp
frame_id
x, y, yaw, speed
acceleration, curvature
```

**验收**

- 三个节点可以独立启动；
- topic 名称和消息定义写入 README；
- 时间戳不倒退；
- 没有订阅者时程序不会崩溃；
- rosbag 回放后结果可重复。

不要把 ROS 2 当成算法本身。它是节点、消息、时间和通信组织方式；
控制器仍然需要独立测试。

### 第 6 周：把 Waymax 结果接入工程管线

**目标**

把现有 Python/Waymax 结果转成 C++/工具可以消费的稳定接口。

**练习**

```text
Waymax trajectory.csv
  -> 解析器
  -> 统一 VehicleState
  -> C++ controller
  -> control_output.csv
  -> Python 指标脚本
```

要求：

- 明确列名和单位；
- 缺列时报错；
- NaN/Inf 时报错；
- 记录输入 SHA256；
- 输出配置和版本信息。

**验收**

同一输入重复两次，CSV 的行数、首尾 timestep 和指标一致。
不要直接把文件名写死成“最新运行”。

### 第 7 周：PyTorch 和训练工程

**目标**

- 理解 Dataset/DataLoader；
- 能写一个小模型；
- 能保存并恢复 `state_dict`；
- 区分训练 loss 和闭环指标。

PyTorch 官方入门教程覆盖 tensor、数据加载、建模、自动微分、优化和保存/加载，
正好对应本课程的行为克隆链路。

**练习**

先用一个小的二维回归数据集，不要马上换大模型：

```text
输入：当前状态特征
标签：目标加速度和曲率
输出：归一化动作
```

必须保存：

```text
model.pt
normalization.json
training.json
```

**验收**

- 新 Python 进程预测一致；
- 训练集和验证集分开；
- 保存 hash；
- 能故意破坏 checkpoint 并让加载失败。

### 第 8 周：闭环训练和错误分析

**目标**

把现有 Day 19–20 的问题变成正式分析流程：

```text
低 loss
  !=
低闭环偏差
```

**练习**

对比：

```text
expert
固定 brake
learned training scene
learned evaluation scene
```

逐帧记录：

- timestep；
- action；
- log divergence；
- offroad；
- overlap；
- 第一个坏帧。

**验收**

写一页错误报告，必须分开：

- 观察事实；
- 当前推断；
- 尚未知原因；
- 下一项单变量实验。

### 第 9 周：性能、调试和可维护性

**目标**

- 能解释一次运行花费在哪里；
- 能区分 CPU 时间、内存和模拟时间；
- 能使用日志和 profiler 定位瓶颈。

**练习**

给 C++ controller 增加：

- 每秒处理状态数；
- 平均和 P95 延迟；
- 最大内存或输入队列长度；
- 每种错误计数。

测试：

```text
空输入
单条轨迹
80 步轨迹
异常时间戳
大曲率
NaN/Inf
```

**验收**

不能只说“运行很快”。要给出输入规模、机器、编译模式、
测量方法和结果。

### 第 10 周：安全边界和故障处理

**目标**

学会把失败设计成可观察、可拒绝、可恢复的状态：

```text
输入非法 -> 拒绝
轨迹不可行 -> 明确错误
控制器超限 -> 限幅并记录
时间戳倒退 -> 停止或降级
指标无有效帧 -> 不报告虚假的 0
```

**练习**

为 planner/controller 增加：

- 输入 schema；
- 状态机；
- 失败原因枚举；
- 降级策略；
- 结构化日志；
- 负向测试。

不要把“程序没有崩溃”写成“车辆安全”。

### 第 11 周：作品集和技术说明

**目标**

将项目整理成招聘方可以在 10 分钟内看懂的仓库。

README 必须包含：

```text
问题是什么
输入数据是什么
系统结构图
如何构建和运行
如何测试
指标定义
一张成功轨迹图
一张失败轨迹图
已知限制
下一步
```

项目至少保留：

- C++ 源码；
- Python 评测脚本；
- CMake；
- 单元测试；
- 配置文件；
- 小型固定 fixture；
- 运行结果摘要；
- 失败案例；
- 复现命令。

不提交本地大数据、私有数据、虚拟环境和大 checkpoint。

### 第 12 周：面试和投递

**算法题**

- 数组、哈希、二叉树、图；
- 二分、排序、滑动窗口；
- 时间/空间复杂度；
- C++ STL。

**项目题**

准备回答：

1. 为什么选择 Waymax 而不是 CARLA？
2. 为什么只控制 SDC，NPC 用日志 fallback？
3. 为什么 loss 很低但验证轨迹很差？
4. 如何保证 reset 起点一致？
5. 如何发现 checkpoint 被篡改？
6. 如果换成 C++，接口如何设计？
7. 如果部署到 ROS 2，消息和时间戳怎么处理？

**投递节奏**

不要等“全部学完”才投。完成一个可运行项目、能解释限制后，
就可以开始投递实习和初级仿真/规划/评测岗位，同时继续补强。

## 就业前最低验收线

### 必须会

- Python 能读、改、测试实验代码；
- C++ 能写一个小型可测试模块；
- Linux/Git/CMake 能独立使用；
- 能解释坐标、时间戳、单位；
- 能跑一次闭环实验并定位失败帧；
- 能写清楚实验边界。

### 最好会

- ROS 2 节点和 rosbag；
- PID/Pure Pursuit/Stanley；
- 基本路径和速度规划；
- PyTorch 基础训练和 checkpoint；
- profiling 和结构化日志。

### 暂时不用追求

- 立刻掌握所有感知模型；
- 立刻训练大规模 RL；
- 立刻搭建完整 CARLA 传感器系统；
- 立刻精通所有自动驾驶模块。
